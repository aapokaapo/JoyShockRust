## DualSense Edge USB input

Linux identifies Sony as `054c` and the second PS5 controller as `0df2`. The driver matches that product on USB and Bluetooth and sends it through `dualsense_create` and `dualsense_parse_report`. SDL explicitly names `0df2` as DualSense Edge. For discovery, enumerate `hidraw` via udev, corroborate a physical USB parent and check `HIDIOCGRAWINFO` on the opened fd. Compare the report descriptor and observed traffic to identify the gamepad interface. The exact USB interface number and endpoint on the target controller remain open. [Linux HID IDs](https://github.com/torvalds/linux/blob/7d0a66e4bb9081d75c82ec4957c50034cb0ea449/drivers/hid/hid-ids.h#L1257-L1266) · [Probe and device table](https://github.com/torvalds/linux/blob/7d0a66e4bb9081d75c82ec4957c50034cb0ea449/drivers/hid/hid-playstation.c#L2823-L2907) · [Parser assignment](https://github.com/torvalds/linux/blob/7d0a66e4bb9081d75c82ec4957c50034cb0ea449/drivers/hid/hid-playstation.c#L1736-L1745) · [SDL USB product IDs](https://github.com/libsdl-org/SDL/blob/402fc52af4e731184ad6a704068b5ccd27d8f1b8/src/joystick/usb_ids.h#L122-L127) · [hidraw discovery and identity](https://github.com/torvalds/linux/blob/7d0a66e4bb9081d75c82ec4957c50034cb0ea449/Documentation/hid/hidraw.rst#L23-L54) · [HIDIOCGRAWINFO](https://github.com/torvalds/linux/blob/7d0a66e4bb9081d75c82ec4957c50034cb0ea449/Documentation/hid/hidraw.rst#L71-L108)

The driver accepts the full USB report only for `BUS_USB`, report ID `0x01` and length 64 bytes including the ID. Its common payload begins at byte 1. Bluetooth uses a different frame and parser branch. The full Bluetooth input report is `0x31`, 78 bytes, with a two-byte prefix and trailing CRC32 checked using the input seed `0xA1`. Bluetooth can also send a minimal report with ID `0x01`. Scope Phase 1 to USB and reject Bluetooth at the transport boundary. ### Calibration and units

- Factory calibration in Linux uses feature report `0x05` of 41 bytes, including the ID. `ps_get_report` checks returned size and ID and applies the feature CRC check on Bluetooth. On USB, the signed LE16 fields start at bytes 1, 3, 5 (gyro biases), 7 through 17 in two-byte steps (per-axis gyro plus/minus), 19 and 21 (gyro speed terms), and 23 through 33 (per-axis accelerometer plus/minus). These are readings from each device. Read the feature once at initialization with `HIDIOCGFEATURE`, with byte zero initialized to `0x05`, when calibration support is implemented. [Calibration ID and length](https://github.com/torvalds/linux/blob/7d0a66e4bb9081d75c82ec4957c50034cb0ea449/drivers/hid/hid-playstation.c#L90-L95) · [ps_get_report](https://github.com/torvalds/linux/blob/7d0a66e4bb9081d75c82ec4957c50034cb0ea449/drivers/hid/hid-playstation.c#L783-L816) · [Calibration decoder](https://github.com/torvalds/linux/blob/7d0a66e4bb9081d75c82ec4957c50034cb0ea449/drivers/hid/hid-playstation.c#L1007-L1050) · [HIDIOCGFEATURE](https://github.com/torvalds/linux/blob/7d0a66e4bb9081d75c82ec4957c50034cb0ea449/Documentation/hid/hidraw.rst#L121-L134)
- Linux expresses its calibrated evdev motion counts in 1024 counts/(°/s) for gyro and 8192 counts/g for acceleration. In this revision it scales gyro readings by the sum of speed terms divided by the sum of the distances from the reported per-axis bias to each calibration endpoint (after accounting for the output resolution). It does not subtract the gyro bias from the sample. Accelerometer calibration subtracts the midpoint and scales the endpoint span to 2 g. The driver substitutes nominal range-based parameters for zero denominators. These output resolutions alone are insufficient to convert hidraw samples. [Output resolutions](https://github.com/torvalds/linux/blob/7d0a66e4bb9081d75c82ec4957c50034cb0ea449/drivers/hid/hid-playstation.c#L166-L170) · [Scaling and fallback](https://github.com/torvalds/linux/blob/7d0a66e4bb9081d75c82ec4957c50034cb0ea449/drivers/hid/hid-playstation.c#L1052-L1126) · [Application to raw samples](https://github.com/torvalds/linux/blob/7d0a66e4bb9081d75c82ec4957c50034cb0ea449/drivers/hid/hid-playstation.c#L1527-L1544)
- SDL HIDAPI applies the gyro bias and uses the difference between the gyro endpoints for gain. It publishes rad/s and m/s², which the fork converts to °/s and g in `GetIMUState`. These formulas can yield different results even on the same controller. Preserve factory data and raw readings, then verify axis signs, scale and stationary bias with controlled motions and six static orientations before choosing the project's conversion. User/stillness bias belongs to the pure motion stage and persistence to configuration. ## Readiness, permissions and coexistence

- `hidraw` reads one queued report per call, includes the ID for numbered reports, can truncate and consume a report when the buffer is too small, and uses a per-open finite queue that skips new reports when full. Use a reusable buffer sized for the interface's maximum report, not a 64-byte buffer that could make a longer frame appear valid. Use level-triggered read readiness, a bounded batch in read order, and resume on the next readiness notification if the budget expires. Treat `EAGAIN` as queue drained, retry an interrupt as appropriate, and treat `EPOLLERR`, `EPOLLHUP`, `EIO` or `ENODEV` as a lifecycle event requiring teardown or diagnosis. Only subscribe to read readiness for a read-only fd. Queue overruns and sample loss must be measured and surfaced.
